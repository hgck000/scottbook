# ScottBook v0.43.0 — release hardening

## Release contract

This release fixes reproducible CI and lifecycle defects in v0.42. It adds no
reading, screen, account, score, or learning feature.

- Keep all 75 built-in articles, 2,550 sentences, annotations, article IDs,
  ordering, progress, favorites, history, imports, and backups unchanged.
- Preserve the Paste/TXT/EPUB `invalid gzip data` fix.
- Keep whole sentences out of Review; only character and word/phrase items are
  retained there.
- Make the generated library identical when produced on Linux, macOS, or
  Windows.
- Do not expose fallback state for interaction before authoritative IndexedDB
  hydration completes.
- Do not let Android Back interrupt the imported-book save transaction.
- Exercise the real cross-library context step in the vocabulary browser
  journey instead of expecting an immediate jump.

## Fixed failures

The pushed v0.42 workflow completed Linux core and Android jobs, but its
Windows, macOS, and Browser journeys jobs failed.

| Area | v0.42 defect | v0.43 correction |
|---|---|---|
| Windows/macOS PWA | The committed generated library was compared with gzip bytes emitted by platform zlib | Generation now uses the pinned pure-JavaScript `fflate` compressor with fixed options |
| Browser journey | The `喜欢` action opens its additional whole-library contexts before it can jump | The journey selects the authored context explicitly, and a unit test requires multiple matching contexts |
| Startup data | Library controls could be used while IndexedDB was still replacing fallback state | The accessible local startup shell remains active until IndexedDB is ready or fallback is confirmed |
| Android import | Back during `saving` claimed cancellation even though the IndexedDB transaction could still commit | Back cancels analysis but is blocked during the non-cancellable commit |

The portable compressor produces a slightly larger library payload than native
zlib: the largest application chunk is about 1,299.25 kB / 682.79 kB gzip and
the root PWA precache is about 1,863.40 KiB. This remains substantially below
the v0.41 baseline and removes platform-dependent generated bytes.
